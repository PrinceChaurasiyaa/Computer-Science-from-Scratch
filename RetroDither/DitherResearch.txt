========================== Google ============================================

A dithering algorithm is an image and audio processing technique that adds controlled noise to randomize quantization errors, creating the illusion of a broader color palette or smooth gradients on limited-display devices.

How It Works

Quantization Reduction: 
Reduces the number of colors or shades (such as turning a 24-bit image into a 16-color or black-and-white file).

Human Visual System: 
Relies on the human eye to blend tightly packed dots of available colors into intermediate tones and shades.

Banding Prevention: Eliminates harsh visual blocks or abrupt color steps (color banding) across smooth transitions.

Common Types of Dithering Algorithms

Ordered Dithering: Uses a repeating matrix (like a Bayer matrix) to compare pixel values against deterministic thresholds, making calculations fast and independent.

Floyd-Steinberg: A popular error-diffusion algorithm that calculates the difference between a pixel's true value and its reduced value, then spreads that leftover error onto neighboring unquantized pixels.

Random Dithering: Adds completely random noise to the signal or image before reducing colors, which prevents repeating grid patterns but can look overly grainy.

======================= Error diffusion =============================================

Error-diffusion is a digital halftoning technique used to convert continuous-tone images (like grayscale or color photos) into a limited color or binary (black-and-white) palette while preserving the illusion of intermediate shades.

How Error-Diffusion Works

Quantization: The algorithm scans an image pixel by pixel (usually left-to-right, top-to-bottom) and rounds each pixel's value to the nearest available color or brightness level in the target palette (e.g., pure black 0 or pure white 255).

Error Calculation: It computes the difference (the "quantization error") between the original pixel value and the new quantized value.

Error-Diffusion: This error is then distributed (or diffused) onto neighboring, unprocessed pixels using specific fractions or weights, compensating for the adjustment in subsequent steps.

Key Concepts and Algorithms

Floyd-Steinberg Dithering: The most famous error diffusion method. It pushes the residual error of a pixel to four immediate neighbors: 7/16 to the right, 3/16 to the bottom-left, 5/16 straight down, and 1/16 to the bottom-right.

Noise Shaping: Instead of creating harsh periodic patterns like traditional ordered dithering, error diffusion pushes quantization noise into higher spatial frequencies where the human eye is less sensitive, resulting in sharper detail and smoother gradients.

Advanced Variations: Methods like Jarvis, Judice, and Ninke or Stucki expand the error distribution kernel to a larger neighborhood (12 or more pixels) for higher visual quality at a greater computational cost.



=================== Steps ==============================

1. Find whether black or white is closer to the gray in the pixel. This 
will be based on some kind of threshold. For instance, if the grays are 
stored as 8-bit unsigned integers, there may be 256 shades of gray num
bered 0 through 255, and our threshold could be 127. Any pixel greater 
than 127 may be marked as white (255 in this scheme), and any pixel 
less than or equal to 127 may be marked as black (0).

2. Subtract the difference between the new pixel color and its original 
color. Imagine the original gray was 204. The difference would be  
255 – 204 = 51. This is our error.

3. Add one-eighth of the error to six specific pixels close to the original 
pixel. This is the diffusion step. In this case, 51 // 8 = 6 (we need to do 
integer division). The pixels adjusted are: one to the right, two to the 
right, one diagonally down and left, one diagonally down and right, 
one straight below, and one two below.



================================ The MacPaint File Format=============================================


1. What is MacPaint?

MacPaint was a painting program created by Bill Atkinson and released by Apple in 1984 with the original Macintosh.

It was revolutionary because people could use:

A mouse 🖱️
A graphical user interface (GUI)
Tools for drawing and editing images

Before this, computers often required text commands, and graphical interaction was less common.

2. Why was MacPaint limited to black and white?

The original Macintosh had limited hardware capabilities.

MacPaint supported only:

Black = 1
White = 0

It did not support grayscale or color in its original format.

The image dimensions were fixed:

576 pixels wide X 720 pixels tall

That means:

Width  = 576 pixels
Height = 720 pixels

Total pixels:

576 X 720 = 414720

So a MacPaint image contains 414,720 pixels.

3. Why does MacPaint use bits instead of regular pixel values?

This is an important connection to your dithering studies.

Normally, a grayscale image uses 8 bits per pixel:

0 → Black
255 → White

For example:

pixel = 180

This requires 8 bits.

But MacPaint only needs two colors:

Black = 1
White = 0

A single bit can represent each pixel.

Example

Suppose we have 8 pixels:

Black White Black White White Black Black White

Represented as bits:

1 0 1 0 0 1 1 0

These 8 bits can be packed into one byte.

That saves storage space.

4. What is run-length encoding (RLE)?

The paragraph says MacPaint used a compression technique called run-length encoding.

RLE compresses repeated values.

Example without compression

Suppose the pixel sequence is:

000000001111111100000000

There are many repeated zeros and ones.

Instead of storing every bit individually, we can represent runs:

8 zeros, 8 ones, 8 zeros

Conceptually:

(0, 8), (1, 8), (0, 8)

This means:

8 consecutive zeros
8 consecutive ones
8 consecutive zeros
Why is this useful?

Images often contain repeated pixel patterns, such as large white backgrounds.

RLE can reduce the amount of data needed to store those patterns.

Important: The exact MacPaint RLE format has its own rules. The example above explains the general concept, not the complete MacPaint encoding specification.

5. What is a binary file format?

Your Python program will eventually save the image to a file.

There are two broad types of data representation:

Text data

Example:

Hello World

Stored as characters.

Binary data

Example:

01010101 11110000

Stored as bytes and interpreted according to a file format's rules.

MacPaint files use binary data.

The computer needs to know:

Where the header starts and ends.
Where the pixel data is stored.
How the data is compressed.
How to interpret the bytes.

That's why the book says:

Programming against binary file formats is a matter of carefully following a specification document.

You cannot simply write arbitrary bytes and expect MacPaint to understand them.

6. What is a 512-byte header?

The paragraph says:

A MacPaint file consists of a 512-byte header followed by pixel data compressed using run-length encoding.

Think of a file as:

┌────────────────────────────┐
│ Header (512 bytes)         │
├────────────────────────────┤
│ Compressed pixel data      │
└────────────────────────────┘
What is a header?

A header contains information or reserved space that comes before the main file data.

In this format, the header precedes the compressed image data.

You can think of it as:

File = Header + Compressed Image

The header is not the actual image pixels.

It is part of the file structure.

7. What are Mac OS forks?

This is probably the most unfamiliar concept in the paragraph.

The classic Mac operating system stored files using two parts called forks.

1. Data fork

Contains the actual data of the file.

For a MacPaint file, this includes image-related data.

2. Resource fork

Contains additional structured resources, such as information used by applications.

Historically, Macintosh files could use both forks.

Why does this matter?

Modern operating systems, such as Windows and Linux, do not use the classic Macintosh fork system in the same way.

When a classic Mac file is transferred, information from its forks may need special handling.

That's why the book introduces MacBinary.

8. What is MacBinary?

MacBinary is a format used to preserve classic Macintosh file information when transferring files between systems.

The book explains that MacPaint files transferred outside the classic Mac OS should be encoded using MacBinary so their metadata can survive.

Conceptually:

Classic Mac file
       ↓
MacBinary encoding
       ↓
File transferred to another OS

MacBinary adds a special header and packages information associated with the Macintosh file structure.

Simplified structure
┌────────────────────────────┐
│ MacBinary header           │
├────────────────────────────┤
│ MacPaint file information  │
├────────────────────────────┤
│ MacPaint data              │
└────────────────────────────┘

This is a conceptual representation. The actual format has specific fields and alignment requirements.

=============================== Bit Map ====================================

A bitmap is a digital image or memory map made of a grid of tiny dots called pixels, 
where each dot stores specific color information.


How Bitmaps Work

Pixels: 

The grid has rows and columns. Every single pixel holds a color value (like red, green, and blue).

Resolution: More pixels mean a sharper picture. If you zoom in too close, the image gets blurry and you see individual squares.

File Types: Common bitmap (raster) formats include JPEG, PNG, GIF, and BMP. Digital photos and scanned images are always bitmaps.


Bitmap vs. VectorBitmap: 

Stores color data for every single pixel. Great for photos, but files get very large and lose quality when enlarged.

Vector: Uses math lines and curves instead of a grid. Great for logos, because you can resize them infinitely without losing quality.

====================================  Translating Bytes to bits ===============================

In "L" mode, our Pillow Image is encoded using 1 byte per pixel. However, in 
a MacPaint bitmap, pixels are encoded with 1 bit per pixel, meaning each 
byte represents eight pixels. This is a big savings for black and white, and it 
makes total sense since we only need two values (1 and 0) to represent two 
colors.

1. Pillow "L" mode

Each pixel uses 1 byte:

[0, 255, 0, 255, 0, 255, 0, 255]

Each value occupies 8 bits:

1 pixel = 1 byte
2. MacPaint format

Each pixel uses 1 bit:

[0, 1, 0, 1, 0, 1, 0, 1]

 NOTE: 

means converting byte-per-pixel data into bit-per-pixel representation, then storing those packed bits inside bytes.

our first function in macpaint.py is a 
converter that takes the byte array we got from dither() and converts it into 
a “bit array”:

Convert an array of bytes where each byte is 0 or 255
to an array of bits where each byte that is 0 becomes a 1
and each byte that is 255 becomes a 0



================================================ Algorithm ====================================================

1. What does dither() produce?

After dithering, your image contains only two pixel values:

data = [255, 0, 255, 0, 0, 255]

Here:

Pixel value	Color
255	White
0	Black

But each value occupies one complete byte.

255 → 11111111 (8 bits)
0   → 00000000 (8 bits)

So the input uses:

1 pixel = 1 byte
2. What does MacPaint require?

MacPaint uses:

1 pixel = 1 bit

Its convention is reversed:

Pixel	MacPaint bit
White (255)	0
Black (0)	1

For example:

Input pixels:
255  0  255  0  0  255  255  0

MacPaint bits:
 0   1   0   1  1    0    0   1

These 8 bits are packed into one byte:

01011001

Important: The output array still stores bytes. Each byte now represents 8 pixels.

3. Understanding bytes_to_bits()

The function processes 8 input pixels at a time.

for byte_index in range(0, len(original), 8):

Suppose:

original = [255, 0, 255, 0, 0, 255, 255, 0]

It processes all 8 pixels.

Step A: Convert each pixel into a MacPaint bit

next_bit = 1 - (original[byte_index + bit_index] & 1)

For 255:

255 & 1 = 1
1 - 1 = 0  → White

For 0:

0 & 1 = 0
1 - 0 = 1  → Black

Thus:

255  0  255  0  0  255  255  0
 ↓   ↓   ↓   ↓  ↓   ↓    ↓   ↓
 0   1   0   1  1   0    0   1

Step B: Pack these bits into one byte

next_byte = next_byte | (next_bit << (7 - bit_index))

Result:

01011001

Then:

bits_array.append(next_byte)

The output is:

array('B', [89])

89 is the decimal representation of binary 01011001.
